## Backup externo — BLOQUEADO, não comprovado

O snapshot `gsw_v42_predeploy_backup` está na mesma instância e é anterior aos dados atuais. Não protege contra perda total da instância. O ensaio local com dados fictícios prova compatibilidade e restauração lógica, mas não constitui um backup remoto externo.

As ferramentas conectadas consultadas permitem SQL e gerenciamento do serviço; não oferecem um fluxo verificado de exportação criptografada diretamente para um destino externo protegido. Não exportar tabelas reais para respostas de ferramentas, logs, repositório público, artefatos públicos do Actions ou arquivos de texto locais. Não reutilizar automaticamente credenciais existentes em outro ambiente.

Pré-requisitos indispensáveis: destino externo privado aprovado, controle de acesso e retenção, identidade de execução com acesso mínimo, canal seguro para credenciais de leitura do banco, ferramenta de dump compatível com a versão do servidor, chave pública de criptografia cujo segredo de descriptografia permaneça separado. Não ativar serviços pagos para suprir esses requisitos.

Procedimento preparado, ainda NÃO executado com dados reais:

1. Obter snapshot consistente com `pg_dump` em formato custom, incluindo esquema `gsw_sdr`, migrações, índices, constraints, políticas RLS, histórico, revisões, auditoria e opt-outs. Registrar separadamente dependências de roles/grants sem senhas. Conferir extensões/dependências antes de restringir o schema.
2. Executar em runner confiável, sem tracing de shell. Credencial injetada pelo gerenciador de segredos, nunca argumento com senha. Encaminhar stdout do dump diretamente para criptografia autenticada; não escrever dump em claro. Usar `pipefail` para não aceitar arquivo criptografado de dump incompleto.
3. Transferir somente ciphertext para destino externo privado. Registrar SHA-256, tamanho, data, versão do servidor, commit e contagens em manifesto sem dados pessoais. Verificar hash do objeto baixado do destino. Retenção e exclusão devem ser explícitas.
4. Descriptografar em stream para restauração em PostgreSQL isolado, sem conexão de escrita ao banco original. Nunca restaurar sobre desenvolvimento ou produção. Restrição de rede e roles sem acesso a aplicações compartilhadas.
5. Verificar integridade, foreign keys, contagens, comparação exata de mensagens/revisões/opt-outs, permissões e leitura pela V4.1 e candidata. Contagens atuais de referência: 25 conversas, 4 opt-outs, 28 mensagens, 25 rascunhos; recalcular no momento do snapshot. Não usar apenas contagens como prova de integridade.
6. Registrar localização privada, hash e resultado de restauração. Só declarar backup externo válido depois desse ensaio. Não divulgar conteúdo dos registros.

Bloqueio para publicação: falta destino privado externo e caminho de execução/credenciais seguros verificados. Uma autorização genérica de deploy não resolve esse requisito.
